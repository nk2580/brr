# Brr domain

A persistent agent is an optional named identity with reviewed Markdown instructions, `soul.md`, model defaults, scoped recall, learned skills and many conversations. An agent is separate from a task owner, task run, runtime thread and execution lease. Ordinary Brr chats remain available. General agent sessions need no Git folder; new repository work still uses WorkTrunk. A mention assigns a separate reviewed-context task rather than adding a second identity to an existing transcript.

SQLite is the revision authority for agents and learning. Versioned Markdown files are projections. Private agent facts and source evidence are separated by trusted session bindings; derived user/project knowledge can be shared with source provenance. All new baseline, agent and task sessions learn from newly recorded evidence. Existing historical threads are intact and are not backfilled. See [the persistent-agents decision](docs/adr/004-persistent-agents.md).

A workspace is a local project folder selected by the user. A conversation is a persistent runtime thread associated with a workspace. A turn is one user instruction and the agent's resulting work. Items are streamed messages, tool calls, command output, file changes and agent activity within a turn. An approval is a runtime request that must be answered with its original request ID. Read-only access permits inspection; workspace-write permits project edits while keeping the runtime's sandbox and elevation approvals.

New project conversations run in separate Git worktrees managed by WorkTrunk. The selected project folder remains the source for subsequent conversations; the conversation's working directory is its saved worktree location. Resuming keeps that location, and archiving retains the worktree. Existing conversations retain their saved directories. WorkTrunk configuration and approved lifecycle hooks govern creation; missing setup or saved worktree data blocks the affected conversation without falling back to the shared project checkout.

The desktop host is a constrained Tauri bridge. The owned Brr runtime is a source fork of Codex CLI; it owns inference, tools, OAuth and history. Inference is authorized only by a managed ChatGPT login and the built-in OpenAI provider. API keys, externally supplied tokens and custom inference providers are excluded.

WorkTrunk is a pinned source submodule compiled into the desktop host as a native library. Setup inspection and explicit approval are local host operations. The app displays exact project hook templates, records only the approved templates and preserves the instruction for a later send. No installed WorkTrunk executable is required. Fresh Git identity reads support the long-running host without trusting stale CLI process caches.

A collaboration mode determines how the runtime works with the user. Default mode can implement a task; Plan mode explores, asks clarifying questions and produces a proposed plan using the runtime's built-in instructions. Plan mode is separate from the progress checklist and from workspace permissions. A proposed plan is ready for implementation only after its authoritative final Plan item arrives. The user can continue planning or explicitly start implementation in the same conversation. Steering adds instructions to the active turn and retains its mode.
