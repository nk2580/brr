# Brr existing interface

- Tickets is a permanent rail destination between Agents and Plugins, with its own project sidebar and Home project-menu shortcut. A fixed Todo / In progress / Review / Complete board uses compact cards, manual ordering, visible linked execution states, pointer movement and keyboard alternatives. Ticket details expose editable title, Markdown description, checklist, agent/priority, comments, activity and published run evidence. Both the ticket panel and Agents Decisions show the complete execution snapshot before explicit approval. Preserve chat and ticket drafts across navigation, refresh only authoritative remote data, and keep the board locally editable while runtime access is unavailable. At 800 by 600, scroll the board horizontally and expand details within the main content area.

- Intelligent UI responses sit inline in the transcript and reuse Archivo, shared theme tokens and compact controls. Native comparisons, diagrams, charts and forms choose layouts suited to their content. Headers provide View text, Reset and Expand; custom apps also provide Stop/Run. Expand uses an interactive-response workspace tab with shared state. Generated source remains separate from Brr-owned chrome. Follow-ups use a compact, keyboard-accessible review above the composer with the exact prompt and captured inputs, Cancel and explicit Send; drafts and Plan mode remain intact. At the native minimum, the transcript scrolls and controls stay within the conversation width.

Derived from the supplied ChatGPT desktop reference and the verified Brr interface.

- Use the Brr public site's shared theme in `src/theme.css`: Archivo variable weights 400–900, ink at 16% lightness, base surfaces at 21% and 27%, paper text at 96%, muted text at 75%, and a line role at 34%. Use the stronger control-border role for form fields, the saved theme color for focus and app accents, and shared semantic roles for danger, warning and success. Interface text uses Archivo and the fixed product type scale; monospace is for code and technical content only. The permanent rail and full top toolbar share the selected appearance color. Settings > Appearance > Theme color retains all nine saved choices; apply each choice to both bars and app accents while keeping the contextual menu surfaces neutral. Graphite uses paper highlights; Blue and Violet use brighter matching accents for readable focus and text. Apply the accent tokens at the document root so body-portalled menus and dialogs inherit them. Rail and toolbar icons, hover and focus follow the selected palette, with disabled toolbar controls visibly distinct. Third-party MCP iframe content remains provider-owned; Brr-owned host chrome uses the shared theme.
- A 35px toolbar spans the desktop with space reserved for native macOS window controls. The 52px icon rail stays mounted; the adjacent 330px sidebar has a rounded top-left corner and collapses independently. Chat fills the remaining width, including the released sidebar space. At narrower windows the sidebar uses 250px and then 230px at the 800px native minimum. Sidebar scrolling is independent from the rail and transcript. The collapsible chat list has no account footer; account details, authentication and reconnect controls live on Profile.
- The menu is contextual: Home shows projects and chats, Agents shows the agent list, and Plugins shows plugin/MCP categories. Only the active section's menu occupies the space beside the rail. The shared toolbar control targets that menu; collapsing releases its width to the main section. Home's chat menu stays hidden while Agents or Plugins is selected. Section headers and content sit inline beside their menus.
- Archivo is used throughout the conversation, headings, navigation, menus and settings, with a fixed product scale and clear weight hierarchy. Monospace is reserved for code and technical paths. Sidebar navigation and project names use 14px text; recent chats use 13px, with captions remaining at least 11px. Projects use folder disclosure rows with indented chat children; Recents show the saved conversations. Long titles truncate. The fixed rail contains Home, Agents and Plugins at the top, with the user profile avatar followed by a Settings gear at the bottom. All five have hover and keyboard-focus tooltips. They select destinations independently of sidebar visibility; they never collapse the sidebar. Profile fills the workspace beside the rail, with a clear heading, account email and existing authentication actions on the shared surface. Contextual menus are hidden while Profile is active, with their saved collapse state retained. Close or Escape returns to the previous section and focuses the avatar. Repeated activation stays on Profile; rail navigation switches sections normally.
- The composer uses a 64–200px growing message field and one compact footer. An icon-only Add context button, Project and Plan stay on the left; the model selector, Chat options, Send and running Stop stay on the right. Attachment cards and errors sit above the footer, with no empty attachment row. Context and running-action menus open upward; Escape dismisses them and restores their trigger focus. Shrink labels before the primary actions at the native minimum. Reasoning, chat identity, access policy and worktree details live in the keyboard-accessible Chat options popover. A selected named agent appears on its trigger, and new read-only chats show a lock indicator. Use an 18px container radius and a neutral focus border; individual controls retain visible keyboard focus. Preserve drafts, selected settings, planning shortcuts and the 800x600 minimum.
- Pending agent questions replace the message composer in the current chat. Show one question at a time in the same composer surface, with compact suggested choices, a borderless custom-answer field and a small progress/navigation footer. Next preserves the draft; only the final explicit submit sends answers. Keep the ordinary message draft while questions are open. The transcript keeps compact question and answer summaries with a route back to the active question; do not render a second editable form there.
- Home projects are named buckets with an independent disclosure, selection and action menu. New project opens the shared creation/edit dialog with name, optional folders, remove controls and primary-folder radios; editing includes collapsed new-chat defaults. Use the existing graphite surfaces, Archivo scale and saved accent. New-chat welcome shows “New chat in [project]”, attached paths and a starting-folder marker, or “No folders attached”. Composer project selection preserves rich drafts and provides No project; existing chats offer Move chat to project. Delete ungroups chats into Recents, while Archive all chats is separate. Workspace tools choose a saved resolved folder and keep existing tabs pinned to their chosen root. Keep dialogs keyboard accessible and bounded/scrollable at 800x600. See [project chat buckets](docs/adr/008-project-chat-buckets.md).
- Use the existing Button primitive and lucide icon vocabulary. Keyboard focus uses the existing outline; disabled and pending actions remain visibly distinct.
- Planning adds a compact composer mode control and an inline proposed-plan review/action. Reuse current border, surface and spacing conventions. Appearance settings use named native radio choices and local-device persistence, with a Graphite fallback for absent or invalid preferences. No generated raster assets, display typography or decorative animation are needed.
- Composer controls fit the 800x600 native window in either sidebar state without hiding Send or Stop. Only the dedicated toolbar toggle expands/collapses the adjacent sidebar; its saved state, draft and active transcript are preserved. New chat and Search live inside the sidebar. Home returns to the current conversation and retains its draft and sidebar state. Repeated Agents, Plugins and Settings clicks stay in the chosen section. The whole rail remains visible and unchanged in either layout.
