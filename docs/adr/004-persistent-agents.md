# Persistent agents and host-owned work

Status: accepted for implementation; acceptance evidence is tracked under `projects/agents`.

Agents are optional named identities layered over ordinary Brr conversations. Each has reviewed Markdown instructions and a soul, defaults, independent sessions, and separately owned tasks. Creating or editing a profile first produces a candidate. SQLite stores its exact hash and base revision; only the native user-review endpoint can approve it. Application compares those values and materializes versioned Markdown atomically. A chat tool cannot grant itself review authority.

The app-owned `brr-agent-core` crate keeps profiles, immutable thread bindings, scoped memory, source revisions, skills, task graphs, runs, fences, workflows and events in one SQLite database. The database is authoritative. Markdown is a readable projection. Profile snapshots refresh at turn boundaries without replacing the runtime's immutable policy or collaboration mode instructions.

New baseline, named-agent and task threads contribute new evidence. Historical threads are never rebound or backfilled. Raw evidence is private to its originating agent or thread; sharing a project does not share transcripts. Derived user and project facts can be shared automatically with their source references retained. Model publication uses exact source revision tokens and rejects corrected or forgotten evidence. Forgetting tombstones affected derivations immediately. Undo checks intervening mutations. Learned procedures require verified successful tool evidence and are loaded through a compact index and scoped read tool.

The host injects typed dynamic tools and per-turn `additionalContext` using existing APIs in the pinned Codex fork. Profile JSON is application context subordinate to policy and current requests; factual recall and skill content are untrusted data. Renderer RPC policy does not permit callers to choose tools, developer instructions, providers or these context fragments. Existing authentication checks remain in both host and owned runtime. Managed agent/task/learning threads disable native temporary-agent spawning and goal continuation; baseline threads retain their existing temporary-agent behavior.

The host alone starts and continues managed task turns. Every run has an immutable thread binding and a fenced lease. A completed turn alone never completes a task: a matching completion proposal, evidence and authoritative successful turn settlement are required. Generated delegation is a proposed graph until the user approves its exact hash. Mentions create a separate task with explicit message context. Recurrence instantiates fresh dependency graphs, coalesces missed occurrences and prevents overlap; IANA time zones select the earlier repeated local minute and skip nonexistent local minutes.

The default task capacity is four background workers total and two task workers per agent; these are editable defaults. At most one lower-priority learning worker shares the global budget. Direct conversation turns use the ordinary runtime path. Repository tasks get native WorkTrunk worktrees, with exact setup-hook review; non-Git tasks use their selected folder with writer coordination. General chats need no Git project.

Closing a window hides it while the process continues. Explicit Quit checkpoints/stops work. On restart the host reconciles durable bindings and runtime history before continuation. An unresolved external effect is an actionable blocked outcome, never an instruction to replay the original request. Brr has no separate always-running daemon or remote worker. Private memory is a harness recall boundary under existing local tool permissions, not filesystem confidentiality from authorized shell access.
