# 007: Local project tickets and reviewed execution

Status: user-approved; implementation and acceptance tracked under `projects/tickets`.

Tickets are durable project work records in the app-owned `brr-agent-core` SQLite store. The registered stable project ID supplies identity across project folders and isolated worktrees. This follows the user's explicit integration decision after the concurrent project-model change. Ticket state is Todo, In progress, Review or Complete, with one fixed board column per state. Projects without folders use the project model's private app-owned scratch workspace for reviewed execution. Missing registered folders permit local planning but block execution. Execution uses the sole folder automatically or requires an explicit folder choice for a multi-folder project. Hidden projects retain their records.

Keep the shared AgentStore available independently of runtime startup. Local UI ticket operations use a constrained main-webview endpoint. Runtime dynamic tools share the service but derive actor, source thread and default project from trusted host bindings and retain task lease fencing. Ordinary, named-agent and task sessions can explicitly manage tickets across registered projects. Interview, profile and learning sessions have no ticket tools. Project sharing exposes ticket content and published task results, not private transcripts.

Tickets and execution Tasks are distinct. Creation, assignment and status writes have no dispatch effect. A human may review and run a ticket; a model may only propose a run. The durable proposal hashes the resolved execution snapshot, chosen original folder, project configuration and ticket revision. Approval verifies freshness and atomically creates the Task, link, activity and operation result. First start revalidates the approved configuration and uses that same project snapshot for reservations and workspace preparation. Saved sessions retain their persisted roots during recovery. The task's immutable session keeps the stable project scope and all reviewed workspace roots; the chosen folder determines its initial working directory. Preserve the reviewed workspace permission on start, continuation and recovery. Existing Tasks without the new optional field keep their previous behavior.

Only one unfinished linked Task may own a ticket, including paused, blocked and waiting work. Enforce the invariant on retry and recovery as well as creation. Runtime-turn attachment, rather than scheduler claim, supplies the automatic In progress event. Successful fenced task settlement with submitted evidence supplies Review. Both transitions occur with their lifecycle transaction. Separate explicit status revisions prevent delayed events from overwriting a user's or agent's later intent. Completion evidence is submitted under existing task rules and is not independent certification.

The board uses Brr's existing theme, typography and controls, with keyboard alternatives to pointer movement and usable layouts at 800 by 600. Tickets are shared project artifacts, not a replacement for private recall, runtime history or repository project notes. V1 has no external synchronization, customizable workflows or automatic pickup.
