# Conversation-first chat

Status: accepted; implemented in the working tree. See the current checks and platform limits in the [delivery record](../../projects/desktop-agent/conversation-first.md).

Brr keeps its existing appearance, navigation and persistent Agents model. DeepSeek Harness revision `ce7073d51254c26cd63b22a60835b8f948deb447` informed the interaction design; its packages and rendering framework are not imported. The composer uses Lexical's plain-text editor with Brr-owned semantic references, quotes, selection, attachments and settings. Plain-text copy is portable. Each conversation and unsent new chat has a separate durable draft in app-owned SQLite. Successful chat creation promotes the originating draft into the runtime conversation without replacing another chat's draft.

The host validates semantic ranges, workspace references and typed submissions. Agent references assign a separate task with only the submitted message and explicitly selected context. Quoted text and file references cannot acquire assignment authority. Workspace file references resolve against the saved execution snapshot, independently of subsequent sidebar moves or project edits. Opening a reference uses the same host-resolved root and path.

One host coordinator handles foreground Send, Queue and Steer under the existing question guard. Running Enter queues; Cmd/Ctrl+Enter steers the expected active turn. Every submission has an immutable ID and settings snapshot. Authoritative history reconciles pending previews by that ID. Missing acknowledgements mean uncertain delivery and never authorize automatic replay. Successful completion can dispatch the next queued message; questions and approvals block it. Stop, failure, disconnection and restart pause dispatch until explicitly resumed. Learning evidence is recorded once after accepted delivery.

Attachments are imported into private app storage and referenced through opaque IDs. Only selected originals are staged read-only for the target runtime conversation. The owned runtime denies access to the chat registry and other conversations' originals, strips source grants on forks and rejects unmanaged attachment permission profiles. Image capability is checked before delivery. UTF-8 text and images have previews; other documents retain their original files without built-in PDF or Office extraction. macOS enforcement requires a separate OS sandbox check in addition to pure permission matching; no other-platform support claim follows from compilation.

The transcript retains turn identities and keeps assistant answers visible. Stable work groups preserve disclosure choices without unnecessarily remounting interactive responses or MCP Apps. Copy, Quote and Reuse prepare content without sending. Streaming follows only while the reader follows the bottom; semantic anchors preserve earlier reading positions across growth, disclosure and navigation.

Editing an opening prompt forks before that turn. Branch from here includes a completed turn. Steering text can be copied, quoted or reused but does not establish another branch boundary. Queues stay with their original conversation. Branch history does not grant fresh question, approval or interactive authority, and is not fresh learning evidence.

A branch uses the source chat's **current working files**, even when its chat history ends earlier. Git roots are captured consistently, including tracked edits, deletions, executable modes and non-ignored untracked files. Destination worktrees receive those files before approved destination setup hooks run. Source switch hooks do not run because the source workspace is not switched. Git metadata, ignored files and staging state are not copied. Conflicts, nested repositories and unsafe filesystem entries are rejected. Selected non-Git folders remain shared; chats without selected folders get fresh private scratch space.

Branch creation journals preparation, runtime fork, identity binding, execution snapshots and attachment grants. Incomplete branches cannot begin inference. Recovery adopts only a proven runtime fork; ambiguous operations retain their paths and remain pending. Deleted sidebar projects leave recovered branches ungrouped while preserving historical execution scope. Named-agent identity, canonical scope and access policy remain host-controlled.

Brr materializes a frozen selected history prefix for persistent paginated forks, including history preceding compaction, so completed branches remain discoverable after restart. Empty edit-before-first-turn branches are represented by validated ready branch journals until their first accepted message. Their current draft may be edited or blank. Archiving marks the journal only after runtime success and prevents the draft row returning after restart.

Saved messages whose runtime chat is unavailable have a separate recovery view. Complete active/archived inventory and a metadata-only lookup distinguish missing chats from readable reference-backed history. Viewing or copying never starts inference. Definitely failed or undelivered queued messages may restore into a new unsent draft with validated context; accepted, dispatching or uncertain delivery remains read-only. A durable source mapping makes restoration idempotent even after draft promotion. Restoring a queued message cancels its original queue entry atomically. Recovery never silently resends.

The Rust host and owned Codex runtime remain authoritative. ChatGPT-only inference, existing approval and Plan gates, and sandbox boundaries continue to apply. Lexical's MIT license is included in application resources; runtime and WorkTrunk changes are recorded in their provenance notes.
