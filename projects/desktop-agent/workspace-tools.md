# Workspace tabs beside chat

Replace the Activity button with an icon opening a new tab in a resizable right panel. A new tab offers Browser, Terminal, Git diff and Files. Tabs survive closing the panel and switching app sections; closing a dirty tab asks before discarding. Keyboard users can resize with left/right arrows and select tabs with arrows/Home/End. At the minimum 800×600 window, the chat list temporarily closes to leave room for chat and tools.

Expand workspace panel fills the workspace beside the permanent rail, hiding the chat and contextual sidebar while keeping their state mounted. Restore split view returns the previous split width and sidebar preference. Tabs, notes and unsaved file edits survive both actions. Adding browser notes to a message restores the split so the draft is visible for review. The resize handle is available only in split view.

Terminal, Files and Git use the original project folder captured when the tab is opened. Agent execution remains in its persisted isolated worktree. The path stays visible above project tools. Changing chats does not redirect existing tabs to another folder.

The browser uses a native child webview rather than an iframe, so ordinary sites can load without iframe restrictions. It has address navigation, history, reload and element annotations. Notes stay local to the tab until Add notes to message appends them to the originating chat draft; the normal Send action sends the reviewed message. Notes collected before a first message follow that same new conversation when it gains its saved thread id. Switching chats never transfers browser ownership or notes. Page popups are accepted only from the active foreground-owned tab.

The owned `brr_browser` dynamic tool is available to baseline and named-agent foreground chats. It opens/lists tabs, snapshots visible page text and control refs, and performs typed click/fill/key/scroll/navigation actions. Remote content is untrusted data. Tasks, learning and profile interviews receive no browser tool. A Brr-only owned-runtime endpoint refreshes the host-owned catalog after resuming a saved chat, retaining the current turn tool snapshot and persisting updates through the existing runtime mechanism.

Native workspace commands accept only the local main app view. Remote child webviews receive no Tauri capabilities. HTTP/HTTPS and about:blank are the only browser URL schemes. Browser callbacks use JSON data rather than arbitrary generated JavaScript. Native manager caps browser tabs at 12; the terminal caps live sessions at 4.

Terminal uses xterm and a real PTY with bounded output, serialized visible polling, resizing and close cleanup. Files supports nested navigation and UTF-8 files up to 2 MiB, explicit Save and Cmd/Ctrl+S, stale-version rejection, serialized Brr saves and atomic replacement. Canonical containment and Git metadata exclusions apply to symlinks too. External filesystem mutations during the final check/rename interval remain a platform filesystem race. Git is read-only and shows staged/working, deleted and untracked file changes, with bounded patch output and binary states.

Native acceptance reproduced and fixed a macOS Wry panic from reading a new about:blank view URL before its WKWebView had a URL. Creation returns the requested URL and page-load events track later navigation; blank tabs wait quietly until navigation before polling page content. After subscribing, each tab reads its cached location once so agent navigation completed before listener registration is recovered; newer location events take precedence over that read. The actual embedded page annotation flow, explicit draft append, native file save reflected in Git, real PTY cwd/output and five successful agent browser tool calls were verified in the packaged app.

Behavioral regressions observed before fixes include missing workspace entry, structured browser results/document-start registration, old-chat catalog refresh, skipped PTY output, concurrent stale writes, Git metadata aliases, deleted-file diffs, dirty reselect, out-of-order file/diff responses and stale root responses. Current verification is recorded in evidence/workspace-tools/verification.json. Windows shell selection is implemented but Windows native acceptance is not available on this macOS host.
